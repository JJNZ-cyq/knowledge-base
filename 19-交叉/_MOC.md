## 判断顺序（第一个命中即定）

| 判断 | 归属 | 例子 |
|---|---|---|
| 只涉及 1 个领域？ | → 该领域目录 | "UE 用户均衡的 Wardrop 条件" → `10-交能融合/02-交通流分配` |
| 是**用编程做领域的事**？ | → **领域目录** + `#prog` 标签 | "Gurobi 建 TN-PDN 调度模型" → `10-交能融合/01-能量调度` |
| 是**编程语言本身的特性**？ | → `12-编程与工程` | "pybind11 返回 numpy 数组的所有权" → `12-编程与工程/混合栈` |
| 是**方法论**，可跨领域复用？ | → `15-优化方法论` | "双层规划的 KKT 转化条件" |
| **两个顶层领域相互增强**？ | → **本区** | "LLM 自动生成优化模型" |

| 子目录 | 装什么 | 为什么算交叉 |

## ⚠️ 最容易搞混的一条

**"用 Python 解决交能融合问题"不是交叉，是领域内的日常工作。**

这个误判的代价很大：如果按"涉及两个领域就放交叉"来做，
`10-交能融合` 的两个子区会被逐渐掏空，只剩下空目录。

判据很简单：**问"删掉编程，这个知识还成立吗"**
- 成立 → 放领域（如"充电负荷的时空分布怎么建模"）
- 不成立 → 放编程（如"pybind11 怎么返回 numpy 数组"）
- **两个领域各自的知识都不足以产生它** → 才是交叉
