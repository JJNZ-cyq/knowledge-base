### 日常推送（唯一需要记住的命令）

```
cd E:\知识学习
tools\push.cmd
```

`push.cmd` 会：暂存全部改动 → 提交（无改动则跳过）→ 推送。
首次运行自动加 `-u` 建立跟踪。

**为什么要用 `.cmd` 而不是 `.ps1`**：

| 方式 | 结果 |
|---|---|
| `.\tools\push.ps1` | ❌ 报错：`因为在此系统上禁止运行脚本`（UnauthorizedAccess） |
| `.\tools\push.cmd` | ✅ 正常（`push.cmd` 内部带 `-ExecutionPolicy Bypass`） |

原因：本机 PowerShell 执行策略各作用域均为 `Undefined`，Windows 客户端默认为
`Restricted`。`.cmd` 不受该策略约束，所以用包装器绕开，**无需修改系统安全设置**。

> 如果你更想能用 `.ps1` 直接跑，一次性的正规解法是：
> `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`
> 但本库不需要——用 `push.cmd` 更省事。

### 网络说明

| 时间 | 环境 | TLS 出站 | 结果 |
|---|---|---|---|
| 2026-09-23 | Agent 沙箱（workspace-write） | ❌ 被禁 | `schannel: SEC_E_NO_CREDENTIALS` |
| 2026-09-24 | Agent 沙箱（full-access） | ✅ 放开 | push 成功 |

**结论：Agent 环境的网络权限会随策略变化。** 你在自己终端里跑 `push.cmd` 始终可用；
只有在终端也失败时，才需要配置代理：

```powershell
git config --global http.proxy  http://127.0.0.1:10809
git config --global https.proxy http://127.0.0.1:10809
# 取消代理
git config --global --unset http.proxy
git config --global --unset https.proxy
```

### 故障：push 报 `non-fast-forward`

说明远端有你本地没有的提交（例如在网页上改过文件），**不要强推**，先拉取变基：

```powershell
git pull --rebase origin main
tools\push.cmd
```
