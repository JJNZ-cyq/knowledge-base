## 一、结论先说：100 天里你只需要约 45 天

这个教程是**通识型**的（作者骆昊），覆盖面很广，包含 Web 开发、爬虫、数据库、机器学习。
但你的目标是交能融合方向的**优化建模**，这些大部分用不上。

**要做的三段**：

```
Day 01-20   基础语法          ← 你说忘光了，必须补
Day 21-30   文件与数据处理前奏  ← 直接服务于数据处理
Day 66-80   NumPy/pandas/可视化 ← 你的核心目标
```

| 段落 | 内容 | 判定 | 理由 |
|---|---|---|---|
| **Day 01-20** | 变量/运算符/分支/循环/列表/元组/字符串/集合/字典/函数/面向对象 | ✅ **必做** | 编程地基，你正好忘光了。跳过这段后面全是空中楼阁 |
| **Day 21-30** | 文件读写、异常、序列化、CSV、Excel、Word/PPT/PDF、图像、邮件、正则 | ✅ **必做** | 数据处理的前置。做 21/22/23/24/25/30 天即可，26-29 可扫一眼 |
| Day 31-35 | Python 进阶、Web 前端、Linux | ⚠️ 只做 Day31 | Day31 讲切片/推导式/生成器，**必看**；32-35 跳 |
| Day 36-45 | MySQL / SQL / Hive | ❌ **跳过** | 优化建模用 CSV/Excel 就够了，不需要数据库 |
| Day 46-60 | Django Web 开发 | ❌ **跳过** | 与你的目标完全无关 |
| Day 61-65 | 爬虫、并发、Selenium、Scrapy | ❌ **跳过** | 用不上。若以后要抓交通数据再回来 |
| **Day 66-80** | 数据分析概述、NumPy×4、pandas×6、可视化×3 | ✅ **核心** | 你的主要目标。**这段是本计划的重心** |
| Day 81-90 | 机器学习（KNN/决策树/回归/聚类/神经网络） | ❌ **暂不做** | 属于另一个方向。等你做优化建模时再考虑 |
| Day 91-100 | 团队协作、Docker、部署、面试 | ❌ **跳过** | 与你无关 |

**省下的 55 天不是浪费，是没必要的弯路。**

## 二、节奏（约 4 个月）

按每周 5 小时算：

| 阶段 | 教材 | 周次 | 每篇用时 | 小计 |
|---|---|---|---|---|
| 一 · 基础语法 | Day 01-20（20 篇） | 第 1-6 周 | 约 1 小时/篇 | 20 h |
| 二 · 文件与数据前奏 | Day 21-25, 30（6 篇） | 第 7-8 周 | 约 1 小时/篇 | 6 h |

> 如果某篇 40 分钟就搞定了，说明你之前没忘那么多，直接进下一篇。

## 四、和知识库怎么配合（重要：大部分篇目不用写卡）

**核心原则：不要为每篇教程写一张卡。** 20 篇语法写 20 张卡是低效的——
语法细节查文档就行，不需要背。

真正值得写卡的只有三类：

| 卡型 | 什么时候写 | 例子 |
|---|---|---|
| **踩坑卡**（最重要） | 任何报错你解决了 | "`KeyError` 但键明明存在"、"`SettingWithCopyWarning` 是什么" |
| **知识卡** | 某个概念**你用自己的话讲不清**时 | "pandas 的 `loc` 和 `iloc` 到底差在哪" |
| **知识卡** | 能与你方向连接时 | "用 pandas 做时间序列重采样"（负荷曲线按小时聚合要用） |

**明确不需要写卡的**：`for` 循环怎么写、`if` 语法、字符串有哪些方法——
这些查文档就有，写卡只是抄书。

**唯一必须养成的习惯**：报错解决了就写一张踩坑卡。命令：

```powershell
cd E:\知识学习
node tools/new.mjs 踩坑卡 --domain 12-编程与工程 --sub Python --title "症状一句话"
```

## 五、三个最容易踩的坑

**1. 只看不敲。**
编程是动手技能。看教程时的"懂了"是假的。**每读 20 分钟就自己敲一遍**，
敲不对的地方才是学习真正发生的地方。

**2. 追求"全部学完"再往下走。**
Day 46-60（Django）你可能完全看不懂，**那是正常的，不用管**。
教程是给所有人写的，不是给你一个人写的。按本计划的取舍走。

**3. 想先把基础全部补完再碰数据处理。**
如果你 Day 01-20 做得顺利，可以直接跳到 Day 66-80 —— **那才是你的目标**。
基础语法不需要"学完"，够用就行。

## 六、什么时候开始学 C++

**不是现在。** 启动条件是下面任一条成立：

- 要写仿真内核，纯 Python 跑不动
- 优化模型规模上来，求解前后的数据处理成为瓶颈
- 需要读某个 C++ 库的源码

C++ 是**性能语言**，不是入门语言。它解决的问题是"已经能跑，但太慢"。
你现在没有"太慢的东西"，学了没有着力点。

学的时候用 `12-编程与工程\CPP\` 三个子目录：
`语言特性`（语法概念）、`工程实践`（踩坑）、`坑清单.md`（症状→原因速查）。
