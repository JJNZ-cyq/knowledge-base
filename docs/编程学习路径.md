# 🧭 编程学习路径（Python → C++）

> 面向**零基础**，目标方向是交能融合（能量调度 / 交通流分配）。
> 这份文件回答"学什么、按什么顺序、怎么算学会"，不堆资源清单。

---

## 零、先定三件事

| 决定 | 结论 | 理由 |
|---|---|---|
| 先学哪个 | **Python 先** | 学完第一阶段就能开始做优化建模；C++ 学完第一阶段只能写命令行计算器 |
| 要不要同时学 | **不要** | 基础语法互相打架（缩进 vs 分号），精力被切半，两边都到不了"能写东西" |
| C++ 什么时候学 | **等你发现 Python 太慢时** | 它是"性能语言"不是"入门语言"，解决的问题是"已经能跑但太慢"。现在没有"太慢的东西"，学了没着力点 |

**C++ 的具体启动条件**（满足任一再开始）：
- 要写仿真内核，纯 Python 跑不动
- 优化模型规模上来，求解前后的数据处理成为瓶颈
- 需要读某个 C++ 库的源码

## 一、四个阶段总览

每周约 5 小时，四个阶段约 4 个月。

| 阶段 | 周次 | 目标 | 验收标准 |
|---|---|---|---|
| 1 · 编程基础 | 1-4 | 能写 100 行脚本 | 不查教程能写出一个读文件、处理、输出的小工具 |
| 2 · 科学计算 | 5-8 | 能处理真实数据 | 给一份 CSV，能读进来、洗干净、画出能进报告的图 |
| 3 · 优化建模 | 9-14 | 能建最小优化模型 | 不看教程能写出跑通、结果合理的光储充电站日前调度模型 |
| 4 · C++ | 15+ | 见上"启动条件" | — |

## 二、阶段 1 · 编程基础（第 1-4 周）

**原则：不碰任何领域知识，只搞清"编程是什么"。**

| 周 | 内容 | 当周产出 |
|---|---|---|
| 1 | 变量、类型、条件、循环、函数 | 3 个小程序：猜数字、单位换算、九九乘法表 |
| 2 | 列表、字典、字符串处理 | 文本统计脚本：读文件 → 数词频 → 输出结果 |
| 3 | 文件读写、异常处理、模块 | 把上周脚本拆成多文件，理解 `import` 与包结构 |
| 4 | 类与对象（**能看懂即可**）+ 复习 | 整合成一个小工具，提交到 git |

> **这一阶段的目标不是"学会 Python"，是"能自己写出一段有用的代码"。**
> 语法不懂就查，不要试图记住所有细节。

**卡住时的处理**：任何报错都写成一张**踩坑卡**（`12-编程与工程\Python\语言与生态\`），
格式是「症状 → 根因 → 解法」。三个月后这就是你专属的排错手册。

## 三、阶段 2 · 科学计算（第 5-8 周）

**原则：用你自己的数据，不用网上的示例数据集。**

| 库 | 练什么 | 用你的什么数据 |
|---|---|---|
| **NumPy** | 数组运算、切片、广播 | 一天的负荷曲线（24 点）：算峰谷差、平均、最大值时刻 |
| **pandas** | 表格读写、筛选、分组聚合 | 充电站历史充电量：按小时/按天聚合 |
| **matplotlib** | 折线、柱状、多子图 | 把上面结果画成能放进报告的图 |

**验收标准**：给一份 CSV，你能读进来、洗干净、画出一张图。
做不到就停在这一阶段，不要往下走——阶段 3 全靠这个。

## 六点五、零基础在 Windows 上必踩的 4 个编码坑

这 4 个坑在 Linux/macOS 上**根本不会遇到**，所以网上抄来的代码和教程都不带处理。
事先知道能省好几个小时。（详细版在 `12-编程与工程\Python\语言与生态\`）

| 坑 | 症状 | 解法 |
|---|---|---|
| **`print` 中文乱码或崩** | `UnicodeEncodeError: 'gbk' codec can't encode...` | 脚本开头加 `sys.stdout.reconfigure(encoding="utf-8")` |
| **读文件中文乱码** | 读出来的中文是 `锟斤拷` 之类 | 所有 `open()` 都显式写 `encoding="utf-8"` |
| **`.ps1` 脚本中文报错** | `因为在此系统上禁止运行脚本` / 中文变乱码 | 脚本内容只用 ASCII；或加 UTF-8 BOM |
| **`.cmd` 批处理中文崩** | 中文注释被当成命令执行 | `.cmd` 里只用 ASCII |

> **一句话原则**：Windows 上凡是"程序与终端/文件交换文字"的地方，
> 都要显式指定 `utf-8`，不要依赖系统默认值。

## 七、三个最容易踩的坑

**1. 只看视频不动手**
编程是动手技能。看教程时的"懂了"是假的。**每看 10 分钟就自己敲一遍**，
敲不对的地方才是学习真正发生的地方。

**2. 环境折腾上瘾**
装环境、换编辑器、试新工具很爽但零产出。**环境能用就开始写代码**，够用就行。

**3. 想先把基础全部学完再动手**
零基础最容易死在这。基础永远学不完。
按本文件的阶段走，**每阶段都有可交付成果**（一个脚本 / 一张图 / 一个模型），
做完一个再进下一个。
