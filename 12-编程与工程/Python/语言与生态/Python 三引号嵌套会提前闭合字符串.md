# 🐛 Python 三引号嵌套会提前闭合字符串

## 症状
> 写在**报错信息里能搜到的字**。

```
SyntaxError: invalid character '：' (U+FF1A)
```

或者更常见的：

```
SyntaxError: invalid syntax
```

**报错行号落在文档字符串的中间几行**，而不是文件末尾——这是识别本坑的关键线索。
如果报错行在文档字符串内部，几乎可以断定是嵌套闭合。

## 最小复现

```python
r"""说明：注意开头的 r""" 这种写法有问题
后面这行会被当成代码
"""
```

第 1 行的 `r"""` 开始字符串，第 1 行末尾的 `"""` 就把它**闭合**了，
后面的中文变成代码 → 语法错误。

## 根因
> 说清**机制**，不只是"这样写就好了"。

Python 的字符串**没有转义嵌套**的概念：`"""` 就是三个字符，
解析器从左往右扫，遇到就结束当前字符串——它不关心你"本意"是不是想引用它。

所以文档字符串里**不能原样出现三个连续引号**。

## 正确写法

**方案 A（推荐）：文档字符串里不要写三引号，改用说明性文字**

```python
"""说明：文件开头用 r 前缀可以避免反斜杠被当成转义序列。"""
```

**方案 B：不写反斜杠路径**

```python
"""运行：uv run main.py    （在项目目录下）"""
```

**方案 C（确实要写时）：用转义或拼接**

```python
"""这里要写三个引号：\""" 这样转义"""
# 或者拆开
QUOTE3 = '"' * 3
```

## 为什么容易踩

- **`SyntaxError` 的行号具有误导性**：报的是"后面那行有非法字符"，
  人的第一反应是"这行有问题"，于是去改那行，越改越乱
- 写中文注释时特别容易中招：说明里想引用一下"开头写了 `r"""`"，
  顺手就把自己闭合了
- 报错信息里出现的是 `U+FF1A`（全角冒号）这类**中文标点**，
  看起来像"中文编码问题"，容易往编码方向查（其实是解析问题）

## 排查方法

报 `SyntaxError` 且**行号不在文件末尾**时，从该行往上找最近的 `"""`，
数一下引号个数是不是 3 的倍数。不是 → 就是本坑。

## 一行速查

```
SyntaxError 行号在文档字符串中间 → 三引号嵌套提前闭合 → 文档字符串里别写三个连续引号
```
